# BuildMe Pilot Validation Methodology

## What Counts as a Ground-Truth Observation

A ground-truth observation is a record that contains ALL of the following:

1. **Project record** — created by an engineer in BuildMe
2. **BuildMe estimate** — generated by the estimation engine and saved to the project
3. **Tracking activated** — project status set to "active" or "completed"
4. **Final cost recorded** — actual final construction cost entered by the engineer
5. **Completion date** — when the project was marked completed

A project is NOT a ground-truth observation if:
- It has no BuildMe estimate
- It has no final cost recorded
- It is still active/incomplete
- It was created as a QA test (QA_TEST_ prefix)

## Validation Status Levels

| Status | Definition | Automatic Upgrade? |
|--------|------------|:------------------:|
| **Unverified** | Project exists but final cost not independently supported | N/A |
| **User Reported** | Final cost entered by the project participant | No |
| **Document Supported** | Final cost supported by uploaded documents (invoices, bills) | No |
| **Independently Verified** | Confirmed by a legitimate independent party | No |

**Rule**: Validation status is NEVER automatically upgraded. Each upgrade requires explicit human action.

## Evidence Requirements

For a project to contribute to validation analytics:

| Requirement | Required? |
|-------------|:---------:|
| BuildMe estimate attached | Yes |
| Tracking status = completed | Yes |
| Final cost recorded | Yes |
| Methodology version recorded | Yes |

For "Document Supported" status:
- At least one evidence document attached (invoice, bill, etc.)

For "Independently Verified" status:
- Explicit independent verification by a third party

## Statistical Thresholds

| Metric | Minimum Sample | Display Rule |
|--------|:--------------:|--------------|
| Any validation analytics | 1+ completed with final cost | Show observational data |
| MAE / MAPE | 3+ completed | Show with warning |
| Bias assessment | 3+ completed | Show with warning |
| Range coverage | 1+ completed | Show with note |
| Breakdowns (by location, type) | 5+ per group | Show only if sufficient |

When sample < 3: Display "Insufficient data for statistical reliability"

## Privacy Rules

Ground-truth analytics NEVER expose:
- Personal names
- Phone numbers
- Exact home addresses
- Bank information

Analytics use:
- Project ID (pseudonymous)
- District/city level location
- Aggregated statistics only

## Methodology Versioning

Every estimate record stores `methodologyVersion`.

Example: "1.0"

When the estimation methodology changes:
- Old projects retain their original methodology version
- New projects use the new version
- Analytics can be broken down by methodology version
- Never mix methodology versions without explicit disclosure

## Exclusion Rules

A project is EXCLUDED from validation analytics if:

1. No BuildMe estimate attached (`missingEstimate`)
2. Still active, not completed (`incompleteProjects`)
3. Completed but no final cost recorded (`missingFinalCost`)
4. QA test project (name starts with `QA_TEST_`)

Exclusion reasons are displayed in the Data Quality section.

## Prediction Coverage

When completed projects exist with both estimate and final cost:

```
range_coverage = projects_inside_range / eligible_completed_projects
```

Where "inside range" means:
```
estimated_low ≤ actual_final_cost ≤ estimated_high
```

This is displayed as:
- "X / Y projects"
- "Z%"

Only shown when ≥1 eligible completed project exists.

## Estimator Bias

```
bias = actual_final_cost - estimated_central_cost
```

Positive bias: BuildMe underestimated (actual > estimated)
Negative bias: BuildMe overestimated (actual < estimated)

Displayed as:
- Mean bias (%)
- Direction (underestimating/overestimating/unbiased)
- Note about sample size reliability
